# NAS 集中化应用实施路线图

**权威设计：** `docs/superpowers/specs/2026-08-25-nas-centralized-app-design.md`

本设计包含四个有严格依赖关系、可独立验收的子系统。为避免把数据库、报告、前端与 NAS 运维混成一个不可审阅的大提交，实施按以下四份计划顺序执行：

1. `2026-08-25-nas-foundation-data-plan.md`
   - FastAPI 应用骨架、配置、PostgreSQL 模型、迁移、登录、CSRF、权限、共享记录、搜索、乐观并发、审计和回收站。
2. `2026-08-25-nas-reporting-files-plan.md`
   - 命名规则跨语言一致性、ReportLab/Pillow 输出、单并发持久任务、File Station 可读目录、哈希与下载。
3. `2026-08-25-dual-mode-frontend-plan.md`
   - 保持 Pages 本地模式，新增 NAS 登录/列表/搜索/管理界面，现有编辑器 API 适配，应急 JSON 导入。
4. `2026-08-25-nas-operations-validation-plan.md`
   - 两容器 Compose、安全约束、数据库权限、备份、Cloud Sync 配置边界、CI、更新、回滚及 DS220+ 隔离真机验证。

## 跨计划验收门槛

- 每份计划必须先通过自身测试，才能进入下一份。
- 后端、报告和前端只能写项目专用测试目录。
- 在本地测试、安全检查和浏览器测试全部通过前，不得连接 NAS 执行写操作。
- NAS 首次写操作前必须验证目标绝对路径不存在或属于本项目，Compose 项目名和容器名不得与现有容器重复。
- 真机初测使用宿主 `127.0.0.1` 专用端口和 SSH 隧道，不开放局域网入口。
- 不列举、不挂载、不修改、不移动、不删除公司现有共享文件夹、容器、Cloud Sync 任务或 DSM 网络设置。
- 只有隔离验证通过后才配置新的 DSM 反向代理和专用报告共享文件夹。
- 最终完成必须同时具备自动测试、浏览器证据、Compose 安全审计、备份恢复证据和 NAS 实机证据。

## 执行方式

用户已明确要求创建持续目标并完成实施，因此计划完成后选择 Inline Execution：在当前 `/goal` 中按任务顺序执行，并在每个阶段提交、复核和更新证据。遇到失败先诊断并修复，不把部分通过当作整体完成。
