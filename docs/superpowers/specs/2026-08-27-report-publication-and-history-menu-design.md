# 报告历史二级面板与办公云盘双目录发布设计

**日期：** 2026-08-27
**状态：** 用户已批准聊天中的双目录方向；本文件是对 `2026-08-25-nas-centralized-app-design.md` 报告存储边界的显式修订。
**目标版本：** `v0.1.10`

## 1. 决策摘要

NAS 正式模式继续以数据库记录和系统归档报告作为权威数据，同时把每次成功生成的四个报告文件发布一份到老师可管理的办公云盘工作区。

File Station 使用现有共享文件夹 `种子创客办公云盘` 下的一个全新、精确、项目专用子目录：

```text
/volume1/种子创客办公云盘/科创诊断报告/
  01_系统归档/
  02_教师工作区/
```

应用容器只挂载这两个精确子目录，不挂载 `/volume1/种子创客办公云盘`、其他公司共享文件夹、共享文件夹父目录或 `/volume1`。现有办公云盘内容、ACL、Cloud Sync 任务和其他子目录不读取、不枚举、不修改。

网页“查看报告”不再使用浏览器 `alert`。它打开站内二级面板，列出全部生成历史，并允许直接打开系统归档中的 PDF/PNG。

## 2. 范围

本次包含：

- 站内“已生成报告”二级面板。
- 生成历史、时间、状态、渲染版本和四类报告入口。
- PDF/PNG 在新标签页直接打开或由浏览器下载。
- 系统归档与教师工作区双目录。
- 双目录的精确 Compose 挂载、运行时配置和 NAS preflight。
- 成功生成后的非覆盖式工作区发布、哈希校验和失败状态。
- 现有项目 `reports-staging` 报告的一次性校验复制。
- File Station 子目录 ACL 和真机验收。
- `v0.1.10` 的 CI、发布、备份、升级和普通应用回滚验证。

本次不包含：

- 让老师在 File Station 修改 PDF/PNG 后反向更新数据库。
- 解析或合并人工编辑过的 PDF/PNG。
- 挂载整个办公云盘或任何其他公司资料路径。
- 修改、暂停、复用或删除现有 Cloud Sync 任务。
- 自动删除系统归档、教师工作区文件或旧 `reports-staging`。
- 增加第三个常驻容器。

## 3. 数据权威性

### 3.1 系统归档

`01_系统归档` 是报告文件的权威位置。网页生成历史、下载 API、哈希和数据库 `generation_records.artifact_manifest` 只引用系统归档中的相对路径。

老师可通过 File Station 预览和下载系统归档，但不能改名、覆盖、移动或删除。管理员可维护。应用 UID/GID `10001:10001` 只对这个精确目录拥有写权限。

### 3.2 教师工作区

`02_教师工作区` 是便利副本，不是数据库权威数据。每次完成的生成记录使用唯一时间目录发布，不覆盖既有文件。老师可在该目录整理、重命名、移动、复制、修改或删除文件；这些动作不改变系统归档、生成历史、报告哈希或学生记录。

需要修改报告内容时，老师回到网页修改学生记录并重新生成。新生成记录建立新目录，不覆盖老师此前整理过的工作区文件。

### 3.3 生成完成语义

报告渲染和系统归档成功后，生成记录可以标记为 `completed`。工作区发布是便利步骤：

- 发布成功：`artifact_manifest.publication.status=completed`，记录四个工作区副本的相对路径、SHA-256 和大小。
- 发布失败：系统归档和网页下载仍有效，生成记录保持 `completed`，但 `artifact_manifest.publication.status=failed`，UI 显示“教师工作区复制失败，请联系管理员”。
- 不在 API、数据库或日志中记录办公云盘之外的公司路径或文件信息。

发布过程使用临时文件、`fsync`、哈希校验和同目录原子改名。一次发布的任一文件失败时，清理该次工作区临时目录，不留下部分可见的四件套；不删除系统归档。

## 4. 路径与命名

两个目录使用完全相同的相对结构：

```text
YYYY年/
  MM月/
    YYYY-MM-DD_批次名称/
      学生姓名/
        HH-MM-SS[-序号]/
          姓名_日期_科创体验报告_无内联.pdf
          姓名_日期_科创体验报告_无内联.png
          姓名_日期_科创体验报告_含内联.pdf
          姓名_日期_科创体验报告_含内联.png
```

继续复用现有 HTML 导出命名函数和路径清理规则。所有相对路径必须通过 `ReportStorage` 根目录边界校验；拒绝绝对路径、符号链接、`..`、控制字符、Windows 保留名和根目录逃逸。

## 5. 容器与配置边界

正式环境新增两个显式变量：

```text
REPORT_ROOT_PHASE=office-cloud-dual
REPORT_ROOT=/volume1/种子创客办公云盘/科创诊断报告/01_系统归档
REPORT_PUBLISH_ROOT=/volume1/种子创客办公云盘/科创诊断报告/02_教师工作区
```

容器内映射：

```text
REPORT_ROOT            -> /data/reports
REPORT_PUBLISH_ROOT    -> /data/published-reports
```

Compose 只允许以上两个精确 bind source。禁止把共同父目录、办公云盘根、其他共享文件夹或 `/volume1` 传给容器。应用仍为非 root、read-only rootfs、`cap_drop: ALL`、`no-new-privileges`；数据库容器和网络结构不变，仍只有两个常驻容器。

本修订替代旧设计中 promoted 根 `/volume1/科创诊断报告`，并仅对上述两个精确子目录放宽“公司共享盘禁写”约束。除此之外，原公司数据非影响边界全部保留。

## 6. NAS 目录所有权与 ACL

在已有 `种子创客办公云盘` 下只创建不存在的 `科创诊断报告` 子目录及两个固定子目录。创建前执行零写入碰撞检查：

- 父共享文件夹必须是 `/volume1/种子创客办公云盘` 的真实非符号链接目录。
- `科创诊断报告` 若已存在，必须具有项目专用 root-owned 标记并通过精确结构校验；否则停止。
- 两个子目录不得是符号链接，不得解析到父目录之外。
- 不枚举或读取同级公司文件内容。

父项目目录写入 root-owned、非容器可修改的隐藏标记 `.makerseed-report-publication-v1`。preflight 同时验证标记内容哈希、UID、权限和两个子目录真实路径。

ACL：

- `01_系统归档`：应用服务身份读写；DSM 管理员读写；指定老师 DSM 组只读；其他账号无权限。
- `02_教师工作区`：应用服务身份读写；DSM 管理员读写；指定老师 DSM 组读写；其他账号无权限。
- 不给 DSM 通用 `users` 组新增权限。
- 不改变办公云盘其他目录的继承或 ACL。

老师 DSM 用户名必须由用户明确提供后才能加入组。应用账号与 DSM 账号继续分离。

## 7. 工作区发布实现

`GenerationJobSettings` 增加可选 `publish_root`。隔离测试模式允许为空；`office-cloud-dual` 模式必须存在并通过路径验证。

生成流程：

1. 保存最新编辑内容并创建 generation job。
2. 在系统归档中渲染四个文件，验证格式、MIME、大小和 SHA-256。
3. 形成权威 `artifacts` manifest。
4. 将四个文件复制到教师工作区同一相对目录的隐藏临时目录。
5. 逐文件验证目标 SHA-256 和大小。
6. 原子发布该工作区生成目录。
7. 把 publication 状态写入同一个 JSON manifest，完成数据库提交和审计。

发布代码只接受来自权威 manifest 的四个相对路径，不遍历办公云盘，不跟随符号链接，不接受调用方传入任意目标路径。

## 8. “查看报告”二级面板

列表页点击“查看报告”后：

- 显示站内 modal/dialog，不使用 `window.alert`。
- 标题包含学生显示名和“已生成报告”。
- 按生成时间倒序显示所有 generation job。
- 每条显示生成时间、状态、渲染版本和工作区发布状态。
- `completed` job 显示四个系统归档文件按钮。
- 点击文件使用同源 `/api/generations/{generation_id}/files/{artifact_id}`，在新标签页打开，设置 `rel=noopener`。
- queued/running 显示状态，不显示文件链接。
- failed 显示用户可读失败摘要，不暴露内部异常。
- 空列表显示“尚未生成报告”。
- API 失败显示错误和“重新加载”，不离开记录列表。
- 支持关闭按钮、遮罩关闭、Escape 和清晰焦点。

下载 API 继续只解析系统归档相对路径；教师工作区文件不能通过修改文件名影响网页链接。

## 9. 现有报告迁移

新增一次性、精确根保护的迁移脚本，只处理：

```text
/volume1/docker/makerseed-diagnostic/reports-staging
```

流程：

1. 读取数据库 generation manifest 中列出的项目相对路径，不扫描公司共享盘内容。
2. 验证每个源文件是 staging 根内的普通非符号链接文件，且 SHA-256/大小匹配数据库。
3. 使用原相对路径复制到系统归档并再次校验。
4. 复制到教师工作区并再次校验。
5. 记录非敏感迁移证据和数量。
6. 不删除 staging；它作为 `v0.1.9` 普通应用回滚的只读保留数据。

任何碰撞、目标已有不同 hash、路径逃逸、符号链接或权限异常都必须在修改该文件前停止。已有相同 hash 可视为幂等通过，不覆盖。

## 10. 更新与回滚

`v0.1.10` 更新仍执行：

1. PostgreSQL 一致性备份。
2. disposable restore verification。
3. 双目录和 ACL preflight。
4. 现有报告幂等复制。
5. 只重建 app，DB container ID 保持不变。
6. 健康检查、登录、报告列表和双目录 smoke。

普通回滚到 `v0.1.9` 时：

- PostgreSQL 不重建。
- `v0.1.9` 重新使用原 `reports-staging`。
- 双目录中的 `v0.1.10` 文件保留，不删除、不修改。
- roll-forward 到 `v0.1.10` 后重新使用系统归档和工作区。

## 11. 测试策略

### 前端

- `查看报告` 打开二级面板而非 alert。
- 多次生成按时间倒序显示。
- completed 显示四个链接，URL、`target`、`rel` 正确。
- queued/running/failed/empty/API error 状态正确。
- 关闭、Escape 和重新加载可用。

### Python

- 工作区发布四件套且 hash/size 与系统归档一致。
- 目标部分失败不留下可见部分目录，不删除系统归档。
- 绝对路径、遍历、符号链接和目标碰撞被拒绝。
- publication manifest 不包含主机绝对路径或公司文件信息。
- 下载 API 始终使用系统归档。

### Compose 与部署脚本

- 只允许两个精确报告子目录挂载。
- 拒绝办公云盘父目录、其他子目录、符号链接和缺失项目标记。
- 仍为两个服务、loopback app 端口、无 DB 端口和既有硬化设置。
- 迁移脚本幂等、只复制 manifest 文件、无 broad delete。

### 真机

- 网页二级面板可直接打开四类文件。
- File Station 中系统归档可预览下载但老师不能修改。
- 教师工作区可整理副本，不影响网页下载、hash 和生成历史。
- 应用容器 mounts 只包含两个精确项目子目录，不包含办公云盘父目录。
- 现有办公云盘其他目录、ACL 和 Cloud Sync 任务未改变。
- 更新、app restart、回滚和 roll-forward 均保留数据库与报告。

## 12. 验收标准

- 点击“查看报告”直接获得可操作的历史报告二级面板。
- 每个 completed generation 在系统归档有四个 hash 验证文件。
- 正常发布时教师工作区有同 hash 的四个副本。
- 老师可以在 File Station 查看系统归档并管理工作区副本。
- 人工修改工作区不影响系统归档、网页下载和数据库。
- 容器无法访问 `种子创客办公云盘` 中任何其他目录。
- 现有公司资料、共享 ACL 和 Cloud Sync 任务没有被读取或改变。
- 全部自动测试、CI、NAS preflight、备份恢复和真机验收通过后才能把 Task 7/8 标记完成。

## 13. 待用户提供的部署输入

代码和本地测试不依赖真实 DSM 账号。真机设置 ACL 前，用户需提供要加入项目老师组的准确 DSM 用户名。没有准确清单时，部署停在双目录创建前，不猜测、不枚举现有 DSM 用户。
